# 中文词典

Run locally with `python3 -m http.server 8081` and open `http://localhost:8081/`.

- `index.html` is the main dictionary page; `css/` contains shared styles and `js/` contains browser scripts.
- `frequency/`, `hsk/`, `subtlex/` (字幕), and `boya/` contain the vocabulary list pages, which share `js/vocabulary-lists.js`.
- `data/` contains the JSON files used by all pages and the durable `word_mapping.csv` ID registry, which should be versioned in Git. The hidden `data/.mapping/` directory contains the scripts and generated working files used to rebuild them; generated intermediate CSVs and the review workbook are ignored by Git.
- Add the account profile picture as `images/profile.jpg` in the repository. The account UI displays this public static image when signed in; change each page's `data-profile-image` value if you use a different file or format. It is served with the site and is not stored in Supabase.
- The data-generation workflow and scripts live in hidden, numbered steps under `data/.mapping/`; it does not use `0 Mapping.xlsx`. Run `python3 data/.mapping/03_build_site_json/build_site_json.py` from the repository root to regenerate all normalized CSVs, update the registry, and rebuild the site JSON. It reads `c cedict.xlsx`, `f Frequency.xlsx`, `h HSK.xlsx`, `b Boya.xlsx`, and `z Subtlex.xlsx` from the repository's parent folder. CEDICT, Frequency, HSK, and Boya provide normalized Pinyin; SUBTLEX-CH has no Pinyin, so its entries use the first Frequency-list mapping for the same simplified `Word` when available, falling back to the first existing mapping. This favors the ranked list's common reading over CEDICT's first dictionary reading for polyphonic words. Unmatched 字幕 entries receive new `w_id` values and blank Pinyin. Of the 6 Boya words without a matching simplified form in CEDICT/Frequency/HSK, 1 reuses its 字幕 mapping and the remaining 5 receive new mappings after 字幕. Existing non-Boya IDs are preserved; removed Boya-only IDs are not reused.
- The durable `data/word_mapping.csv` registry is versioned in Git. Its order is the existing registry followed by new 字幕 mappings and any new Boya-only mappings. The generator adds source IDs (`c_id`, `f_id`, `h_id`, `z_id`, or Boya's `ID`) and `w_id` to normalized source CSVs, then regenerates the ignored `data/.mapping/02_generate_mapping/word_mapping_joined.xlsx` review workbook. JSON records start with `w_id`, the source ID, `Word`, and `Pinyin`, followed by remaining source fields. The SUBTLEX-CH data is written to `data/zimu.json`. The HSK JSON contains only HSK workbook fields; the HSK page looks up CEDICT definitions by `w_id` and shows none when no definition exists. Excel date-converted Frequency Pinyin cells for jun tones are restored during export.
- To convert only one workbook, use `python3 data/.mapping/scripts/excel_to_json.py --excel hsk` (or `frequency`, `cedict`, `boya`, or `subtlex`). A workbook filename or path is also accepted. This exporter only writes the selected raw JSON; run the full build script to apply normalized Pinyin and registry IDs.
- The dictionary, HSK, Frequency, 字幕, and Boya pages show the account and Supabase connection state. Sign in through `/login/` using Supabase Auth email/password; the account link returns to the page and view you came from after sign-in. User Known/Saved state for dictionary, HSK, Frequency, 字幕, and Boya is stored in `public.user_word_state`; each vocabulary JSON record uses its `w_id` to share state across lists. Frequency progress tracks Known words cumulatively across the first 100, 500, 1,000, 5,000, 10,000 (FLUENCY), and 50,000 (about all) entries. On Boya, click a word to toggle its Saved/marked state without changing its position; the “显示已标记” filter appears when any Boya word is marked. A missing row means both flags are false. Run [`supabase/user_word_state.sql`](./supabase/user_word_state.sql) in the Supabase SQL Editor to create the table, unique constraint, index, grants, and row-level security policy. The browser-safe publishable key is configured in the page HTML; never put a `service_role` key in frontend code or share it. The app loads the signed-in user's word-state rows once per page session, so make sure the Supabase API maximum row limit is high enough for that user's saved state.
